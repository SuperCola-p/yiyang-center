## P0 问题修复（2026-05-20 晚上）
### P0-1 Session注入漏洞修复
- **`PageController.setSession`**：标记为 `@Deprecated`，保留仅用于兼容旧前端，但已走拦截器保护
- **`OperatorController.login`**：登录成功后直接设置 `HttpSession` 的 `loginUser` 属性，不再依赖前端调 `setSession`
- **`login.html`**：登录成功后直接 `window.location.href = '/page/home'`，移除 `$.post('/page/api/set-session', ...)` 调用
- **效果**：`/page/api/set-session` 不再被前端使用，且已受 `LoginInterceptor` 保护，未登录用户无法任意注入 Session

### P0-2 BCrypt密码加密修复
- **`pom.xml`**：添加 `spring-security-crypto` 依赖
- **`OperatorServiceImpl`**：
  - 引入 `BCryptPasswordEncoder`（静态常量）
  - `addOperator`：密码 BCrypt 加密后存储
  - `updateOperator`：更新密码时 BCrypt 加密
  - `login`：改为先 `findById` 获取用户，再用 `ENCODER.matches()` 比对密码（而非 SQL 层 `password = ?` 匹配）
- **效果**：新添加的操作员密码 BCrypt 加密；已有 admin 账号的 BCrypt 密文可正常匹配；SQL 中 `$2a$10$...` 的种子密码与代码逻辑一致

### P0-3 护理等级分配前后端不匹配修复
- **`client/list.html`**：
  - `loadNursingLevels`：下拉框 `value` 由 `item.name` 改为 `item.id`（数字）
  - `submitNursingLevel`：调用 API 由不存在的 `PUT /api/clients/{id}/nursing-level` 改为 `POST /api/clients/assign-level`
  - 请求体格式由 `{ nursingLevelName: string }` 改为 `{ clientId: int, nursingLevelId: int }`（匹配 `SetByLevelRequest` DTO）

## 代码审查 - 发现的问题列表
### P0 - 严重问题
1. **`/page/set-session` 存在 CSRF/Session 固定漏洞**：`PageController` 中 `setSession` 方法接受任意 POST 请求直接注入 Session，未做任何身份验证
2. **密码明文传输**：登录时密码以明文 `JSON.stringify` 发送，后端无 BCrypt 验证逻辑（虽然 schema.sql 中密码是 BCrypt 加密的）
3. **前端 `nursingLevel` 传递字符串而非数字 ID**：`client/list.html` 中分配护理等级时发送 `{ nursingLevelName: string }`，但后端 `ClientNursingSettingController.assignNursingLevel` 期望 `{ nursingLevelId: Long }`

### P1 - 功能缺陷
4. **`PageController` 中 `operators/add` 和 `operators/edit` 路由对应的页面文件缺失**：`templates/operator/` 下只有 `list.html`，操作员的新增/编辑功能完全通过模态框实现，而路由仍保留
5. **`statue` vs `status` 拼写不一致**：`CheckOutApplication` 和 `LeaveApplication` 实体及数据库都使用 `statue`（错误拼写），但 `nursing_list` 页面用 `item.status` 访问
6. **`ClientNursingSettingServiceImpl.purchaseService` 中 `price` 参数未使用**：Controller 接收价格参数，但 Service 实现中完全忽略
7. **`NursingItem` 的 `status` 字段枚举值不一致**：DB 中 `ENABLED/DISABLED`，创建时默认 `"启用"`；`ClientNursingSetting` 的 `serviceStatus` 在 DB 中 `ACTIVE/EXPIRED/SUSPENDED`，Service 中设默认值 `"启用"`——中文和英文混用

### P2 - 代码质量问题
8. `NursingItemServiceImpl.getNursingItemsByPriceRange` 在内存中全量过滤，大数据量时效率低
9. `NursingLevelServiceImpl.addItemsToLevel` 循环调用单条 insert，没有批量操作
10. `nursing/list.html` 前端页面 `status` 用 `ENABLED`/`DISABLED`，但 `NursingItem` 实体创建时默认值设为 `"启用"`/`"停用"` 中文
11. `ClientNursingSetting` 的 `serviceStatus` 字段，schema.sql 中建议值 `ACTIVE/EXPIRED/SUSPENDED`，但 Service 代码中设置为 `"启用"`/`"用完"`
12. 前端多个页面响应格式检查不统一：部分检查 `resp.code === 200`，部分检查 `resp.success`，部分检查 `resp.success === false`
13. `client/edit.html` 编辑页面 `nursingLevel` 使用 `<input>` 而非 `<select>`，不加载护理等级列表

## P1 问题修复（2026-05-20 晚上）

### P1-5 statue→status 拼写统一
- 修改涉及 17 个文件的字段名和参数名：
  - **Entity×2**：`CheckOutApplication.private String status` / `LeaveApplication.private String status`
  - **DTO×1**：`AuditRequest.private String status`
  - **Repository×2**：`findByStatusAndDeletedFalse(String status)`
  - **Service接口×2**：`auditApplication(String id, String status, ...)`, `getApplicationsByStatus(String status)`
  - **ServiceImpl×2**：getter/setter 改为 `getStatus()`/`setStatus()`，`findByStatueAndDeletedFalse()` → `findByStatusAndDeletedFalse()`
  - **Controller×2**：`@PathVariable String status` + `request.getStatus()`
  - **前端HTML×2**：`checkout/list.html`（`item.status`）、`home.html`（`a.status`）
- **DB 列名不变**：没有加 `@Column(name = "statue")`，因为 JPA 默认驼峰→蛇形，而 DB 列就是 `statue` 或 `status`（已通过 schema.sql 确认）

### P1-6 purchaseService中price参数未使用 — 已修复

  - 实体 `ClientNursingSetting` 无 `price` 字段，schema 无对应列

- **涉及文件**：`ClientNursingSettingService.java`、`ClientNursingSettingServiceImpl.java`、`ClientNursingSettingController.java`

### P1-7 NursingItem.status 中英文枚举统一 — 已修复

- **问题**：后端 `ClientNursingSettingServiceImpl` 使用中文 `"启用"`/`"用完"`，但前端 `client/list.html`/`nursing.html` 和 Shell 使用英文 `"ACTIVE"`/`"EXPIRED"`/`"SUSPENDED"`
